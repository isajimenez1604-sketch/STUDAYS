STUDAYS - PRUEBAS DE API

BASE:
http://localhost:3000/api/v1

1) REGISTRAR USUARIO
METHOD: POST
URL: http://localhost:3000/api/v1/users/register
Headers:
Content-Type: application/json

Body:
{
  "name": "Ana López",
  "email": "ana@test.com",
  "password": "12345678",
  "confirmPassword": "12345678"
}

Respuesta esperada:
201 Created
{
  "message": "Usuario registrado",
  "user": {
    "id": 1,
    "name": "Ana López",
    "email": "ana@test.com",
    "created_at": "..."
  }
}

2) LOGIN
METHOD: POST
URL: http://localhost:3000/api/v1/auth/login
Headers:
Content-Type: application/json

Body:
{
  "email": "ana@test.com",
  "password": "12345678"
}

Respuesta esperada:
200 OK
{
  "message": "Inicio de sesión exitoso",
  "user": {
    "id": 1,
    "name": "Ana López",
    "email": "ana@test.com",
    "created_at": "..."
  }
}

3) CREAR TAREA
METHOD: POST
URL: http://localhost:3000/api/v1/tasks
Headers:
Content-Type: application/json

Body:
{
  "userId": 1,
  "title": "Estudiar examen",
  "description": "Repasar temas de matemáticas",
  "dueDate": "2026-10-20T18:00:00.000Z"
}

Respuesta esperada:
201 Created
{
  "message": "Tarea creada",
  "task": {
    "id": 1,
    "user_id": 1,
    "title": "Estudiar examen",
    "description": "Repasar temas de matemáticas",
    "due_date": "2026-10-20T18:00:00.000Z",
    "status": "pending",
    "created_at": "..."
  }
}

VALIDACIONES IMPORTANTES:
- Registro exige name >= 2 caracteres
- Email válido
- Contraseña >= 8 caracteres
- login requiere email y password
- task requiere userId > 0, title obligatorio, dueDate si viene debe ser fecha válida

ERRORES COMUNES:
- 400: VALIDATION_ERROR (datos inválidos)
- 401: INVALID_CREDENTIALS (correo o contraseña incorrectos)
- 409: EMAIL_ALREADY_EXISTS (correo duplicado)
- 404: USER_NOT_FOUND (si la tarea apunta a un usuario inexistente)
- 500: DATABASE_ERROR

PREGUNTAS RAPIDAS:
P: ¿Qué puerto usa la API?
R: 3000 por defecto (configurable con PORT).

P: ¿Necesito correr un servidor antes?
R: Sí, primero inician la API con: npx tsx src/main.ts o npm run api

P: ¿Dónde está la BD?
R: En Supabase, con variables en .env.

P: ¿Se prueban desde móvil o web?
R: La API es backend; se consume desde frontend o Thunder Client.
